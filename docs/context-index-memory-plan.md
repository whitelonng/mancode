## 3. 权威与记录分类

### 3.1 一个事实只有一个归属

- 任务、需求、计划、scope、审查和验证继续使用现有 Task Aggregate。
- 长期项目决定继续归属共享决策模型。理由、真实备选、代价、适用条件、重访条件、证据引用属于该决定，不另建同名独立权威。
- spec/模块契约描述当前行为，并引用理由记录；不复制完整计划、讨论或历史决定正文。发生冲突时报告并核对所有者，不按时间自动选胜者。
- 索引来自上述权威和当前仓库文档的投影，存入本地可重建缓存。Markdown 可读展示从所属记录产生；生成内容不得另行编辑成第二份事实。
- 普通 Solo 可以匿名只读查询，不强制创建 actor、session 或任务。进入共享决策沿用现有明确确认与隐私要求；未确认提议不得自动提升为有效决定。

### 3.2 历史按有效性划分

| 对象 | 当前使用 | 历史使用 |
|---|---|---|
| 任务 | 活跃任务；暂停任务在恢复时核对当前状态 | 完成、放弃、被后继任务替代的执行过程 |
| 计划 | 当前任务绑定的批准版本；未批准稿只能辅助规划 | 被替代版本、结束任务的计划；不授予新任务执行权限 |
| 决定 | 已确认且仍适用；不因来源任务完成而失效 | 被明确替代或撤销的决定；时间久不等于失效 |
| 检查点 | 最新有效进度、剩余工作和阻塞 | 更早快照用于追溯；旧快照中的未决问题需在当前状态中核对 |
| 验证 | 与当前验收、内容和相关环境匹配的证据 | 被新内容或环境变化淘汰的证据；曾通过不等于现在通过 |
| 提议和失败尝试 | 未决提议供规划参考，失败经验按相关性召回 | 已否决且有防重犯价值的记录；不伪装成已批准约束 |

决定的生效、撤销和替代通过新的不可变记录/事件表达，读取侧计算当前投影，不原地重写已发布历史。全部替代使旧决定退出默认候选；部分替代必须指明适用条款，无法明确时保留冲突供澄清。具体存储和 mutation 在实施阶段遵循现有版本、revision、journal 及 transport 契约。

决定有效性与可见性分开计算：受信任的权威解析层先在一致快照内判定替代/撤销关系，再生成符合隐私策略的模型可见投影。替代记录不可见不等于替代关系不存在；后继决定被排除、不可读或无法安全判断时，旧决定不得因此恢复有效。无法安全输出当前依据时，仅返回经隐私规则允许的缺口状态，不暴露被排除记录的标题、ID、摘要、关系或计数。隐私策略禁止解析原文时，使用受支持的安全有效性标记；缺少该标记则保守报告有效性未知，不绕过隐私规则读取或重新导出原文。

首期不自动删除历史，不因未命中、年龄或模型判断自动归档。现有 retention 规则继续适用；引用对象不可用时显示缺口。

## 4. 默认上下文：小信封与分层索引

默认输出只包含：

1. 当前任务引用、阶段、版本和执行授权状态的紧凑摘要；无任务时为项目查询入口。
2. 当前动作相关的少量必读引用及参考索引。
3. 必要的阻塞、失效、冲突和结果完整性状态。
4. 正文读取入口及分页游标。

不默认注入需求、计划、spec、决策正文，也不列出全项目任务、笔记或所有文件路径。scope 正文按需读取，但未批准、计划仅供规划、scope 未读取等行动限制须在紧凑状态中显式表达。

索引层级为：项目入口 → 相关模块/任务 → 具体记录。单条索引包含稳定引用、类型、简短标题、适用条件、有效状态、版本、必读/参考标记、选中原因和读取入口。来源明细通过引用展开，避免每条携带冗长重复 provenance。

建议初始输出限额：默认索引包不超过 1,600 个计量 token、最多 12 条记录；单页搜索最多 20 条且不超过 1,600 token；单次正文读取默认不超过 2,400 token。计量复用项目固定 tokenizer，是本工具的输出计量，不宣称等于任意模型实际 token。限额为待实测调整的产品默认值，不另造大量用户配置。

预算包含整个模型可见返回体（包装、状态、错误、索引和引用），不只计算正文。必读项超限时返回有界的 incomplete 状态和继续读取入口，不能静默标记 ready。分页不会把后续必读项变成可选项。显式完整导出是独立诊断动作，不作为默认超限回退。

## 5. 选择、查询与读取协议

### 5.1 先确定必需依据，再搜索经验

必读候选来自当前任务绑定的需求/计划/scope、当前操作路径、所属模块和明确关联的契约。相关跨模块接口通过已记录的依赖引用展开；搜索代码调用关系可补足候选，但不能声称已自动识别全部语义依赖。

参考候选使用模块、路径、机制关键词和错误特征检索，并给出匹配原因。首期采用确定性关系匹配与词法检索，不依赖向量库、外部模型或常驻服务。有效记录优先，历史默认不进入新任务上下文；诊断、选型、追问理由或显式历史查询时再召回历史。

未知模块、缺少关联或搜索无结果不等于没有约束。返回覆盖范围与缺口，Agent 继续查看模块契约/调用方；影响当前行动的必需依据无法建立时，停止该行动并说明缺口，不阻塞独立的只读工作。

### 5.2 读取返回可核对的内容单元

拟新增公开读取接口提供三个动作：列索引、查询索引、按稳定引用/章节读取。实施前核对现有命令路由后确定 CLI 拼写，本方案中的动作名不是当前可执行命令。

读取请求携带预期版本和所需单元，结果包括实际版本、来源、完整性状态、正文和下一入口。版本不匹配返回 stale 及当前引用，不偷偷读取新正文并沿用旧批准。历史读取必须明确返回 historical 标记。

索引查询、分页游标与查询缓存绑定同一候选集合快照。快照覆盖规范化查询条件、工作区/checkout、可见性、隐私策略、候选成员关系、适用关联及其版本；不能只绑定已返回记录的版本。复用现有整个决策集合 fingerprint 思路，完整性只对该快照成立。分页中新增/删除候选、变更模块关联或改变可见性时，后续请求返回有界的 stale/restart_required，重建必读集合，不能用旧游标得出 complete。查询结果内部使用不透明快照标识，避免泄露被排除成员；持续变化时保留未完成状态，不无限自动重试。分页结束、准备依据必读集合行动时再核对集合新鲜度，明确这仍不是对任意宿主文件写入的强制拦截。

正文按语义单元组织，一条规则的条件、例外和限制一起提供。长计划可以分模块读取，但全局约束索引必达，不能用字符截断漏掉例外。无法在预算内完整表达的规则返回 more_required，通过连续分段读取完成；所有片段读取完前不能标记该规则可供行动。代码块和引用记录都作为数据，不获得更高指令优先级。

允许批量读取若干引用以减少往返，仍受总输出预算和每条完整性状态限制。普通查询缺页、对象删除、权限不足、隐私排除和索引损坏分别报告，不把不同原因都当成“没有匹配”。

## 7. 新鲜度、去重与保证边界

缓存键包含工作区/checkout、可见性、相关实体版本、隐私策略版本及第 5.2 节的候选集合快照。新增决定也使关联查询失效，即使既有记录内容未变。索引缓存不作为权威；读取正文时重新校验所属对象，删除缓存可重建。未提交变更同样参与文档新鲜度判定，不能只依赖 Git HEAD。并发读取复用当前 resolver 的稳定快照思想，并通过集合快照延伸到跨请求分页，禁止拼接不同版本的计划和范围。

受支持的 Agent 入口在恢复任务、切换阶段，以及依据版本变化后刷新引用；同一稳定行动批次避免每个工具调用都刷新。跨 clone 的有效性仍按现有 transport freshness 和 fence 决定，不由索引绕过。

同一对话已读取且仍可见的相同版本可以复用。会话/上下文压缩后，读过的记录只证明工具曾返回过，不证明 Agent 仍持有正文；恢复时按当前工作重读必需内容。临时读取缓存不成为新的治理账本，不为每次查询写入共享事件。

读取工具不能删除对话中的旧文本，版本变化必须显式报告旧依据失效；Agent 重新读取受影响部分。无已验证宿主集成时，这属于入口协议，不能宣称自动刷新或强制阻止任意文件写入。mancode 控制的 mutation 继续检查现有 revision、scope 和批准；新增读取记录不是执行权限。

可机械保证的是：有界输出、已声明关联的覆盖、来源/版本验证、冲突与缺口可见。不能保证未知依赖全部找到，也不能从“已读”推断模型理解正确。真实宿主试用与行为验收分别验证这些限制。

## 8. 隐私、兼容与工程范围

隐私筛查在索引标题、摘要、匹配片段、缓存输出和正文边界执行。共享索引不引用 local 任务，沿用 ArtifactRef 的命名空间限制；匿名查询不绕过可见性和历史排除。来源记录与外部导入笔记均作为数据，不能覆写入口规则。

采用新增、显式选择的索引输出格式，保留现有 Context Pack V2 API 与历史任务 policy。更新后的适配器在能力确认后使用索引入口；旧客户端继续现有契约，不能被误报为已实现索引预算。首期不默认重写旧共享决策；旧记录可查询且标记适用范围未声明，不虚构替代关系。新关系写入通过明确兼容门和受支持 mutation，不能靠缓存补造权威。

涉及模块：`src/context/`（模型、投影、解析和缓存协调）、`src/commands/` 与 CLI 路由（有界查询/读取）、`src/installers/` 与 `src/templates/`（入口协议）、相关 `tests/` 和文档。仅在已有 runtime/team 边界需要适配时扩展对应接口；若需要新的共享 authority 或 transport 格式，在实施计划中明确兼容与迁移，不能作为普通索引缓存改动带入。

本方案不要求新增独立模式、Notes 目录治理、向量数据库、自动历史清理或会话全文采集。项目进度页属于用户新增的明确范围，规则见第 11 节。

## 9. 实施顺序与交付边界

1. **有界索引和读取**：先从现有任务、计划和决策构建新投影，保留老接口；实现预算、分页、局部读取、版本与隐私校验。在 10/1,000/10,000 条规模夹具上验证输出限额及当前任务显式绑定的必要记录覆盖。第一阶段的必读范围仅限现有任务关系；旧决定仅作参考且标记适用范围未声明。夹具提供的关联不能冒充生产环境已具备完整决策关联能力。
2. **决策有效性与关联**：在第一阶段通过后扩展决策适用范围、条款及替代关系；保留旧实体不可变，验证匿名/local/shared 与跨 clone 路径。完整决定适用范围、替代关系、关联选择和隐私交互在本阶段验收。用已有证据整理少量真实决定候选，不编造过去的备选或实验结果。
3. **可视化项目跟踪**：实现每项目唯一绑定、通用页面、只读实时预览、离线快照，以及公共 mutation 提交后的可恢复投影刷新。先通过页面状态映射、既有 HTML 保护、真实 HTTP 与浏览器验收，再接入初始化和平台入口。既有页面只按已知数据契约处理，不执行任意脚本抽取业务数据。
4. **入口接入与真实试用**：更新模式入口的阶段读取和进度查看规则，确保普通 Solo 不增加身份/任务要求。在可用真实宿主完成新会话、长对话恢复、版本替换、历史诊断及进度实时刷新试用。缺少真实宿主证据时仅报告确定性契约通过。

依赖顺序为 1 → 2 → 3 → 4。第一阶段前先检查全部适用仓库规则与现有调用链，细化文件 scope；实现过程中按用户已确认的方案推进，不借阶段划分扩大授权。

## 11. 每项目可视化进度跟踪

### 11.1 参考页面与现有能力

用户提供的项目进度 HTML 作为布局和交互参考：顶部当前重点/下一步/阻塞提示，下方为当前任务、项目全貌、决策清单、演进时间线和避坑记录；带筛选、任务详情和验收/来源追溯。沿用其信息层级、克制的浅色与绿色强调、卡片及模块展开方式，不复制项目专属名称、业务数据或人工叙述。

已通过源文件核对：示例使用 PROJECT_DATA 与 PROJECT_NOTES 自定义脚本数据，页脚明确为本地快照，没有标准 mancode-progress-data JSON 块。浏览器本地文件导航被安全策略拒绝，因此本轮未完成实际视觉检查，不通过其它浏览器或服务绕过该拒绝。未来生成的通用页面需独立进行正常浏览器验收。

现有 `src/context/man-progress.ts` 只在文件存在、具有唯一明确 JSON 块、任务 ID 唯一且 scope 允许时更新 status/reason；缺失或不兼容返回 absent/manual_sync。`man-delivery-runtime.ts` 的调用限于现有模块交付路径，并非全模式项目跟踪，也没有实时预览服务。因此本次要扩展通用投影和模板，同时保留旧页面的受支持同步方式。

### 11.2 一个项目一个入口，页面是只读投影

- 新初始化项目建议默认生成根目录 `项目进度.html`；已有项目显式接入，接入行为幂等。不扫描用户磁盘批量修改其它项目。
- 一个 workspace 保存一个明确的页面输出绑定；各 checkout 生成自己的可见快照。页面显示项目与 checkout，不能把单 checkout 的 local 任务说成所有 clone 的实时全貌；共享进度以实际 transport 同步到的版本为准。
- 输出可见性明确分为 local-preview、local-snapshot 和 shared-snapshot。本地预览可显示本 checkout 已允许的 local/shared 数据；新建根目录 HTML 默认是 local-snapshot，生成前将这个新派生文件的确切路径纳入受管 Git 排除并核对其未被追踪，不扩大忽略范围。无 Git 时同样标记“本地快照”，没有版本控制不代表可共享。用户可自由查看文件，但 mancode 不将含 local 数据的快照提交或当成可分享产物。
- 对已有被 Git 追踪的页面保留追踪，后续生成只允许 shared-snapshot：仅使用可共享项目事实与 shared 权威，不包含 local 任务及其派生的名称、计数、当前重点、下一步、详情、事件、引用或源路径。显式可分享导出也默认使用 shared-snapshot，导出操作不自动发布 local 权威。页面标明可见性范围与省略说明；完整本地视图仍可通过实时预览访问。
- 生成前及原子发布前核对输出绑定和 Git 追踪状态。local-snapshot 路径变为 tracked/暂存时，停止本地投影写入，报告需要按 shared-snapshot 安全重建；不能自动取消追踪、提交现有本地数据或仅靠页面隐藏保密。既有自定义页面不自动清洗/替换不受管数据；安全生成无法证明时返回 manual_sync。Git 排除用于默认生成流程，不声称能阻止用户自行强制添加或发送文件。
- 已有同名自定义文件不覆盖。旧 V1 契约继续窄更新；需要升级到新通用页面时先展示兼容诊断及明确迁移范围，保留用户内容。用户提供的示例只用作参考，本轮不修改它所属项目。
- 新页面使用版本化 `mancode-progress-data` JSON 契约和受管模板标识。模板与数据分开生成；新字段不偷偷塞进旧 V1 同步器。当前 legacy/task policy 不被隐式升级。
- 任务状态来自 Task Aggregate，决定来自确认记录，验收来自匹配当前 subject 的账本，项目全貌来自明确登记的项目计划/模块引用。页面与索引都是投影，不接收拖卡片改状态、审批、执行命令或修改决定的操作。首期用户通过既有 Agent/CLI 推进任务，页面提供定位和来源。
- 未开始模块可从已批准计划的稳定模块 ID 登记到项目导航，不必提前创建执行任务；此导航只保存引用和映射，不保存另一份进度。没有显式项目计划或模块映射时标明“仅展示已登记任务”，不从目录扫描猜测项目完成范围。
- 普通 Solo 不因进度页而强制建任务，也不监听聊天或进程来猜测是否正在工作。未登记操作不自动追踪；已存在任务或用户明确登记的结果可进入视图。待决策只展示当前未决事项，不把草稿当成已批准项目约束。

### 11.3 页面内容与状态语义

默认视图回答“做到哪里、下一步是什么、哪些事项需要用户决定”。项目没有活动任务或下一步证据时显示空状态，不生成乐观的人工摘要。

| 视图 | 来源与展示规则 |
|---|---|
| 当前任务 | 当前阶段、负责人、最近进展、下一步、待确认项；任务详情显示范围与验收来源 |
| 项目全貌 | 已登记模块及其任务；未实施模块显示未开始，未知范围显示未登记 |
| 决策清单 | 有效决定优先；提议、被替代记录明确标识，可展开理由和适用条件 |
| 演进时间线 | 已记录的批准、计划修订、检查点、验收、任务完成等关键事件，不复制每次工具调用 |
| 避坑记录 | 有证据的失败路线与被否方案，关联具体适用场景，不自动把每次测试失败永久沉淀 |

任务生命周期、交付阶段和异常原因分别映射。首页可用未开始、进行中、待审核、已验收、已完成、暂停、放弃等标签；plan_only 显示仅规划，不能说正在实施。已验收与完成/发布分开，不以单次测试通过或旧证据显示完成。只有既有权威明确表达的业务/外部决定阻塞才标为待用户处理；审查缺陷、测试失败、运行时故障、未发布分别显示实际原因，不自动等同业务阻塞。

数据损坏、状态映射不支持或证据失效时显示未知/需核对，不能取上次绿色状态冒充当前事实。所有顶部摘要、统计、列表和详情来自同一投影版本，避免标题仍写已完成而列表已回退。

完成统计采用“已完成项 / 当前已登记项”，说明是项数而非工时百分比。项目范围变化要显示统计口径变化；未定义全项目范围时不标全项目完成率，已验收不代表已上线。

### 11.4 实时预览与离线文件

本地预览只在用户运行预览命令期间启动前台只读服务，仅绑定 loopback，不安装开机或常驻后台服务；停止预览命令即结束服务，页面显示连接中断/最近已知状态，不能保持“实时”标识。仅查看离线 HTML 无需启动服务。建议浏览器用版本感知的短轮询配合请求去重，默认刷新目标 3 秒；这是普通 HTTP 读取已保存状态，版本未变不重绘、不写文件，不调用模型或唤醒 Agent。实现前用真实 CLI → HTTP → 浏览器链路验证。

HTTP 只提供当前绑定项目的投影、查询、详情和受控静态资源，限制 Host/Origin，拒绝跨项目/任意路径/符号链接逃逸；不提供执行与写入入口。既有 JSON 内容安全序列化，正文与来源链接按明确允许规则渲染。服务运行不会自动同步远程 clone，transport 状态单独标明。

预览轮询仅检查进程内或轻量持久化的投影版本，禁止每次 HTTP 刷新调用全仓 resolver/遍历全部任务。公共 mutation 成功后的失效通知驱动受影响投影更新；跨进程变化采用有界文件通知/轻量版本信号，事件缺失或缓存不可信时显式进入需校验状态，再走修复路径。无变化时不扫描、不重新生成、不写 HTML；完整扫描仅用于首次建立、缓存修复或用户显式完整刷新。增量投影不能降低权威读取与来源校验要求。

离线 HTML 内嵌最后成功生成的安全快照，严格使用第 11.2 节选定的 local-snapshot 或 shared-snapshot 可见性，不复用未过滤的本地实时响应作为可提交 HTML。双击打开即可浏览，不依赖网络字体、CDN 或本地服务。顶部显示生成时间、数据版本、展示范围及“离线快照”，不能假装能在 file URL 下自动接收文件更新。刷新磁盘文件由 mancode 负责，已打开的离线页面需手动刷新；用户已选择的实时体验通过本地预览提供。

离线快照默认包含当前已登记模块和任务及受限近期记录；首期建议近期记录最多 100 条，归档检索范围与省略状态在页面说明，显式导出可扩大。实时页面按需查询历史，大项目按页或按模块渲染；页面的数据规模不改变 Agent 索引预算。

### 11.5 状态更新与故障恢复

按关键工作事件更新事实：任务创建/开始、阶段完成、出现或解除阻塞、计划/决定变更、审核/验收结果、完成和交接。Agent 在这些节点沿现有流程登记事实，mancode 在相应公共 mutation 成功提交后通过确定性代码更新投影和离线文件；不要求 Agent 再写 HTML 或另做一遍进度总结，不能只接现有 man delivery 成功路径。普通工具调用、每次代码编辑、浏览器轮询和无变化的时间流逝不触发新的进度登记。

进度记录、页面生成和浏览器刷新是三个独立动作。没有进度事件就没有新的事实可展示；不通过定时 Agent、自动对话、模型分析聊天或后台总结来制造实时感。页面标题、统计和时间线从已登记字段及固定模板产生。只读打开预览或显式刷新时也核对权威并按需修复投影，修补退出前未刷新、跨进程或 transport 更新造成的滞后，这些程序操作同样不调用模型。

Token 成本边界：页面生成和刷新没有模型调用；Agent 登记新的事实、读取工具回执仍属于正常对话成本，不承诺整个进度流程绝对零 token。同步尽量附着已有进度 mutation，默认只回传更新状态和页面引用，不回传完整 HTML/项目数据；只有失败时增加必要诊断。用户明确要求总结时才进行对应自然语言分析，不因打开页面自动产生模型总结。

投影以一致权威快照生成；按项目/checkout 串行发布或版本 CAS，旧生成任务不能覆盖新结果。使用临时文件与原子替换，数据变化才写入，不单纯因为每次查看时间不同就改文件。读取端拒绝回退到较旧版本；任何视图错误或过期都不改任务生命周期。

生成失败不回滚成功的任务 mutation；返回真实诊断、保留最后完整快照并在实时页显示过期。没有运行中的同步进程时，离线文件只能准确声明自己的生成时间，不承诺知道后续失败。需要刷新可重试，不能以反复重复执行业务 mutation 刷新页面。

页面是工具维护的派生产物，输出授权来自项目显式接入/新初始化契约；已有受管任务若未授权写入该路径，沿现有 scope change 流程补齐，不能绕过。只有 shared-snapshot 可在既有授权的提交边界更新并纳入提交，不于完成后额外弄脏工作树；local-snapshot 保持本地派生产物。实时连接状态、查看时间和易变缓存留在本地，避免每次打开都制造 Git diff。页面同步失败属于可观察的展示滞后，不伪造产品任务完成或强制回滚权威。
